# 如何运行DHT11上位机程序（含MQTT功能）

## 问题已解决！✅

编译问题已经修复，程序现在可以正常运行了。

## 快速运行方法

### 方法1: 直接运行编译好的exe（推荐）

**程序位置**:
```
D:\A大三上学期实验课\ZigBee无线传感网络\上位机\DHT11_1\DHT11\DHT11\bin\Debug\DHT11.exe
```

**运行步骤**:
1. 双击运行 `bin\Debug\DHT11.exe`
2. 程序会显示完整的界面，包括：
   - 左侧：串口配置、数据格式选择
   - 中间：温湿度显示、图表
   - 右侧上方：**MQTT配置区域**（新增功能）
   - 右侧下方：接收日志

### 方法2: 使用Visual Studio运行

1. 用Visual Studio打开项目
   - 打开 `DHT11\DHT11\DHT11.csproj` 文件

2. 按 F5 或点击"开始调试"

3. 或按 Ctrl+F5 点击"开始执行(不调试)"

## MQTT功能在哪里？

程序运行后，在界面的**右上方**可以看到MQTT配置区域：

```
┌─────────────────────────────────────┐
│  MQTT服务器:  [192.168.184.221:1883]│
│  [连接MQTT] [断开MQTT]  ● 未连接    │
│  ☑ 自动发布数据到MQTT               │
└─────────────────────────────────────┘
```

### MQTT功能使用步骤：

1. **启动MQTT服务器** (如果还没启动)
   ```cmd
   cd emqx-5.0.26-windows-amd64\bin
   .\emqx.cmd start
   ```

2. **在上位机中配置MQTT**
   - 服务器地址框中输入：`192.168.184.221:1883`（默认已填写）
   - 或本地测试：`localhost:1883`

3. **连接MQTT**
   - 点击"连接MQTT"按钮
   - 状态指示器变为"● 已连接"（绿色）
   - 接收日志显示连接成功信息

4. **接收串口数据**
   - 连接串口
   - 选择数据格式
   - 当接收到温湿度数据时，会自动发送到MQTT服务器
   - 日志中显示：`[MQTT发送] 温度:XX°C 湿度:XX%`

## 为什么之前看不到MQTT功能？

### 问题原因：
1. **MQTTnet库引用错误**: 项目使用了PackageReference方式，但.NET Framework项目需要传统的dll引用
2. **编译失败**: 由于库引用问题，程序无法编译
3. **运行的是旧版本**: 运行的exe是之前没有MQTT功能的旧版本

### 已修复的内容：
✅ 从LCW项目复制了MQTTnet.dll
✅ 修改了项目文件，使用正确的dll引用方式
✅ 修正了输出路径（obj\Debug → bin\Debug）
✅ 重新编译生成了包含MQTT功能的新版本

## 验证程序是否包含MQTT功能

运行程序后检查：

1. **界面检查**:
   - 控制面板右侧是否有"MQTT服务器"输入框
   - 是否有"连接MQTT"和"断开MQTT"按钮
   - 是否有"自动发布数据到MQTT"复选框

2. **日志检查**:
   - 程序启动时，日志是否显示："MQTT客户端已初始化"

3. **文件检查**:
   - `bin\Debug\`目录下是否有 `MQTTnet.dll` 文件（大约322KB）

## 常见问题

### Q: 双击exe没有反应
**A**:
1. 检查是否有杀毒软件拦截
2. 右键exe → 属性 → 解除锁定
3. 确保.NET Framework 4.7.2已安装

### Q: 提示找不到MQTTnet.dll
**A**:
1. 确保 `MQTTnet.dll` 和 `DHT11.exe` 在同一目录
2. 重新编译：在DHT11\DHT11目录下运行 `dotnet build`

### Q: 连接MQTT失败
**A**:
1. 确保MQTT服务器已启动
2. 检查服务器地址和端口是否正确
3. 如果是本地服务器，尝试使用 `localhost:1883`
